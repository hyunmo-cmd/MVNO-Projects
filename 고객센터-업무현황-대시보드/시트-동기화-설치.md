# 업무 현황 시트 동기화 설치 안내

통화(수신·발신)·채널톡 데이터를 구글 시트에서 관리하면, 1시간마다 Supabase로 동기화되어 대시보드 **업무 현황** 탭에 표시됩니다.

```
구글 시트 '업무 일별' → Apps Script(work-sheet-sync.gs, 1시간 트리거)
  → Supabase Edge Function(sheet-sync) → work_daily_sheet 테이블 → 대시보드
```

- **후처리**는 시트의 수신 건수 × 5분으로 자동 계산합니다. 발신 건수에는 붙이지 않습니다.
- **개통**은 지금처럼 **업무 입력**(AI 입력·직접 입력)에 저장된 기록을 사용합니다.
- 기존 DB의 '유선 상담'·'채널톡'·'후처리(전화 상담)' 기록은 삭제하지 않지만, 업무 현황에는 더 이상 쓰지 않습니다.

## 1. 시트 만들기

시트 이름은 `업무 일별`입니다. 1~5행 중 한 행에 아래 헤더를 넣어 주세요. 열 순서는 바뀌어도 됩니다.

| 날짜 | 상담사 | 수신 건수 | 수신 시간 | 발신 건수 | 발신 시간 | 채널톡 건수 | 채널톡 시간 |
|---|---|---|---|---|---|---|---|
| 2026-05-01 | 김순옥 | 42 | 1:05:30 | 3 | 0:10:05 | 12 | 0:30:00 |

- **한 행 = 하루 × 상담사 1명.** 같은 날짜·상담사가 두 줄 있으면 동기화가 중단됩니다.
- **시간 열**은 서식 > 숫자 > 맞춤 날짜 및 시간 > `[h]:mm:ss`로 지정합니다. 24시간을 넘어도 그대로 적으면 됩니다.
- 시간을 **숫자**로 넣고 싶으면 헤더에 단위를 붙이세요. 예: `수신 시간(초)`, `채널톡 시간(분)`. 단위가 없는 숫자는 오류로 처리됩니다.
- **상담사**는 실명으로 적어도 됩니다. 전송 직전에 `김*옥`처럼 마스킹되어 실명은 Supabase에 저장되지 않습니다.
- 건수·시간이 모두 0이거나 빈칸인 업무는 전송하지 않습니다. 고객 정보(전화번호·고객명 등)는 이 시트에 넣지 마세요.

## 2. Supabase 설정 (콘솔에서 직접)

1. **SQL Editor**에서 [`supabase/sql/001_work_daily_sheet.sql`](supabase/sql/001_work_daily_sheet.sql) 내용을 붙여넣고 **Run**을 누릅니다.
   - `work_daily_sheet`(업무 일별 집계)와 `sync_logs`(동기화 기록) 테이블이 생성됩니다.
2. **Edge Functions** > Deploy a new function > Via Editor를 선택합니다.
   - 이름: `sheet-sync`
   - 코드: [`supabase/functions/sheet-sync/index.ts`](supabase/functions/sheet-sync/index.ts) 전체를 붙여넣고 Deploy를 누릅니다.
   - 함수 설정(Details)에서 **Enforce JWT Verification을 끕니다.** 인증은 아래 비밀값으로 합니다.
3. **Edge Functions > Secrets**에 비밀값을 추가합니다.
   - Name: `SHEET_SYNC_SECRET`
   - Value: 추측하기 어려운 긴 문자열. 예를 들어 터미널에서 `openssl rand -hex 32`로 만든 값을 씁니다.
   - `SUPABASE_URL`과 `SUPABASE_SERVICE_ROLE_KEY`는 Supabase가 함수에 자동으로 넣어 주므로 따로 등록하지 않습니다.
4. 함수 URL을 복사합니다. 형식: `https://<프로젝트ref>.supabase.co/functions/v1/sheet-sync`

> service_role 키와 `SHEET_SYNC_SECRET`은 GitHub, 대시보드 HTML, 시트 셀에 절대 넣지 마세요.

## 3. Apps Script 설치 (스프레드시트에서 직접)

1. `업무 일별` 시트가 있는 스프레드시트에서 **확장 프로그램 > Apps Script**를 엽니다.
2. [`work-sheet-sync.gs`](work-sheet-sync.gs) 전체를 붙여넣고 저장합니다.
3. **프로젝트 설정(톱니바퀴) > 스크립트 속성**에 두 가지를 추가합니다.
   - `SYNC_URL` = 2-4에서 복사한 함수 URL
   - `SHEET_SYNC_SECRET` = 2-3과 같은 값
4. 편집기 상단의 함수 선택 드롭다운에서 함수를 고르고 **실행** 버튼을 누릅니다. 웹 앱 "배포"는 필요 없습니다.
   1. `previewWorkDaily`: 전송 없이 시트 양식만 검사합니다. 처음 실행할 때 권한 승인 창이 뜹니다. **Supabase 설정 전에도 실행할 수 있습니다.**
   2. `syncWorkDaily`: 최초 전체 반영을 합니다. 결과는 자동으로 생기는 `동기화 로그` 시트에서 확인합니다.
   3. `installHourlyTrigger`: 1시간 간격 자동 동기화를 등록합니다. 한 번만 실행하면 됩니다.

## 동기화 규칙

- **중복 방지:** 날짜 + 상담사 + 업무(수신/발신/채널톡) 기준으로 1건만 저장합니다. 같은 행을 다시 보내면 값이 갱신됩니다.
- **삭제 반영:** 시트에서 지운 행은 다음 동기화 때 DB에서도 지워집니다.
- **안전장치:** 시트 오류(날짜·시간 형식, 중복 행)가 하나라도 있으면 아무것도 전송하지 않고 `동기화 로그`에 행 번호를 남깁니다.
- **급감 방지:** 전송 행 수가 기존의 절반 미만이면 시트가 잘린 것으로 보고 중단합니다. 대량 삭제가 의도된 경우에만 `syncWorkDailyAllowShrink`를 한 번 실행하세요.
- **로그 위치:** 실패 기록은 시트의 `동기화 로그`와 Supabase `sync_logs` 테이블 양쪽에 남습니다.
- **연도 변경:** 날짜를 연-월-일로 저장하므로 해가 바뀌어도 코드 수정이 필요 없습니다.

## 남은 연결 작업

대시보드(`docs/cs-dashboard.html`)는 아직 **삭제된 이전 Supabase 프로젝트** 주소를 가리키고 있습니다. 새 프로젝트의 URL과 Publishable key로 교체해야 업무 현황에 시트 데이터가 표시됩니다.

현재는 로그인 기능이 없어서, publishable 키로 `work_daily_sheet`를 읽을 수 있게 열어 두었습니다. 저장되는 정보는 마스킹된 상담사명과 집계 수치뿐입니다. 로그인을 붙이면 SQL 파일의 읽기 정책을 `authenticated` 전용으로 바꿉니다.
